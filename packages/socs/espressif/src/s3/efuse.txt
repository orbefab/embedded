# The eFuse sets an `esp32s3` part can name, one section each. Each line under `[name]` sets one
# field of block 1 or block 2. Copy, for that field, the raw unsigned value `espefuse summary`
# prints in parentheses, in decimal, `0x` hex or `0b` binary. Copy `MAC` as the address summary
# prints. Copy `PSRAM_CAP` and `PSRAM_CAP_3` as those two lines. Do not copy `PSRAM_CAPACITY` or
# `WAFER_VERSION_MINOR`: espefuse calculates them (`PSRAM_CAP_3 << 2 | PSRAM_CAP`, and
# `WAFER_VERSION_MINOR_HI << 3 | WAFER_VERSION_MINOR_LO`) and they are not fields IDF reads. An
# ADC field's meaning column is sign-and-magnitude, and `adc_info` decodes it that way; the
# parentheses are what IDF reads, so raw `0x81` is 129, not `-4`. A field a set does not name is
# 0, and so is all of block 0. The field names and places are IDF v5.5.5's
# `components/efuse/esp32s3/esp_efuse_table.csv`, one csv field each, and `efuse.rs` holds them.
# A name that is not one of those fields, the two calculated names included, is an error.

# A revision 0.2 chip with 8 MB of PSRAM in the package and no flash in it, block version 1.3,
# the MAC 02:00:00:00:00:01 and every calibration field 0. With BLK_VERSION_MAJOR 1, IDF reads
# the ADC calibration from eFuse and takes each field's 0 as no offset from its nominal value.
[synthetic]
MAC 02:00:00:00:00:01
WAFER_VERSION_MINOR_LO 2
BLK_VERSION_MINOR 3
PSRAM_CAP 1
PSRAM_TEMP 2
PSRAM_VENDOR 1
BLK_VERSION_MAJOR 1
