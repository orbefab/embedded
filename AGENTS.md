# AGENTS.md

- `docs/` holds only finalized docs. Raw plans, drafts and notes do not go into the repo.
- A core crate (`packages/cores`) never names a vendor's registers, and a chip crate (`packages/socs`) never decodes a CPU's instructions. [docs/engine/README.md](docs/engine/README.md#cores-and-chips) says why.
- Run `scripts/check.sh fast` before every commit; it skips Rust lint and tests when only docs, site or non-CI `.github` paths changed (`ORBE_CHECK_ALL=1` runs everything), and heavy check scripts take turns on a per-user machine lock outside CI. CI runs the engine, viewer and site checks on every pull request. Run `scripts/check.sh full`, which adds the browser speed check, before a release and on a change meant to make the engine faster, and run `scripts/diff-esp32s3.sh` by hand before a release. The headers of [scripts/check.sh](scripts/check.sh) and [.github/workflows/ci.yml](.github/workflows/ci.yml) say what each tier runs and what CI runs when.
- `apps/orbe/skills/core.md` holds only the rules, the build loop, one worked example, troubleshooting and the routing table. A new feature goes in its topic skill, with a routing row when it needs one, and never in core or `skills/orbe/SKILL.md`. Skill prose is short and has no long decimals.
- A release tag ships every part, Block and skill on main, and the catalog keeps a published part for good. So a feature that takes more than one PR lands its engine code unwired, where nothing a user runs reaches it. Its parts, Blocks, skill text and README lines land together in one launch PR once it works end to end.
